Three decisions you should know about, since generated service code will be written against them:

1. **`Do` takes `HTTPClient`, not `*blogger.Client`.** There is no `blogger` package anywhere in this repo — `go.mod` declares module `github.com/itokun99/blogger-go` and requires `google.golang.org/api v0.250.0`, but that module is not in the local module cache (only `.mod` files are), so an import of a nonexistent internal package could never compile, and `*blogger.Client` would break `go build` outright. `Do(client, responseModel)` therefore accepts an interface; `*blogger.Client` satisfies it automatically once the package exists, so the signature stays source-compatible with the task spec. Base path is read through an optional `BasePathProvider` interface.
2. **`PageToken` is the constant, not the type.** The task mandated `PageToken = "pageToken"` in options.go and `type PageToken string` in pagination.go — identical package-scope identifiers, which Go rejects. The constant won (it is wire-correct); the type is `Token`, with `NewPageToken` as the constructor.
3. **`Do` returns `(interface{}, error)`** per spec, returning the same `responseModel` pointer it filled, and `nil, nil` when `responseModel` is nil.
